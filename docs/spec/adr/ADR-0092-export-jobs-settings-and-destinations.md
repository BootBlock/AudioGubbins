# ADR-0092 — An Export Renders Canonically, Encodes, Stages, And Only Then Delivers Under A Collision Policy

- **Status:** Accepted
- **Decision:** Phase 09's readiness review places export in a new, portable `packages/import-export` (`@audiogubbins/import-export`), which owns the typed settings, the presets, the job state machines and the collision rules, and takes every effect through injected ports.
  - **One settings model.** `ExportSettings` is a discriminated record per format: WAV (integer 8, 16, 24 or 32 bits, float 32 or 64, A-law, µ-law, IMA or Microsoft ADPCM; plain, extensible or RF64 by need), AIFF and AIFF-C, FLAC (16, 24 or 32 bits, compression level), MP3 (constant, average or variable bit rate, quality), Ogg Vorbis (quality or nominal bit rate), Opus in Ogg (bit rate, mode, frame length, complexity) and AAC in M4A (bit rate); with, for every format, the sample rate, the channel layout and its conversion, the dither (none, rectangular or triangular, with or without noise shaping), the range (the project, a region, every region, or the selection), the metadata policy and fields (`ADR-0093`), and the file name template. Every value is validated against the format's `CodecDescriptor`, and an invalid setting is refused with the reason, never clamped.
  - **Presets over the full settings.** An `ExportPreset` is a name and a partial `ExportSettings`; resolving it fills every omitted value from the format's defaults and gives the same typed record the expert controls edit (`REQ-AUDIO-050`). The built-in presets cover game effects (WAV 16-bit at 48 kHz, Ogg Vorbis, Opus), masters (WAV 24-bit and 32-bit float, FLAC) and distribution (MP3 at 320 kbit/s and V0, AAC). The person's own presets are kept in their preferences, raising `userPreferences`. A change to any value in the expert controls is kept as edited settings, never lost to a preset. The default is the highest-quality path for the format: the project's own rate and layout, 32-bit float for WAV and AIFF-C, the highest FLAC depth the source needs, and the highest quality of a lossy format, with no conversion the person did not ask for (`REQ-AUDIO-143`).
  - **The job.** An `ExportJob` is a state machine: `planned`, `rendering`, `encoding`, `staged`, `delivering`, `delivered`, and `failed` or `cancelled` from any state before `delivered`. The render worker renders the range through the canonical engine at the target rate, with the effect racks, the conversion to the target layout as graph nodes (`ADR-0060`), and the dither as the last step before integer quantisation, from a generator seeded by the job's settings so the same export gives the same bits (`REQ-ARCH-049`). Rendered blocks pass from the render worker to the codec worker, and encoded bytes from the codec worker to the storage worker, over message channels; the page sends commands and receives progress. A batch export is a list of jobs run one at a time, with progress for each and the whole.
  - **Staged before delivered.** The storage worker writes the encoded body into an export staging area in the origin-private file system; a container whose header depends on the whole stream (FLAC's stream information, MP4's movie box, MP3's information frame) is completed when the stream ends. Delivery then writes header and body to the destination; only a whole delivered file is reported as exported, and an export that fails or is cancelled leaves the destination as it was. A delivery refused for permission or collision keeps the staged file, so the person can retry or choose another destination without rendering again; staging is a cache category removed after delivery and at start, never a root. The storage estimate is checked before rendering, for the staged file.
  - **Destinations.** A destination is a save dialog's file, a chosen folder, a kept trusted folder, or a download where no dialog exists (`REQ-GODOT-046`). A folder delivery writes through `createWritable`, which replaces a file only when it closes, so no destination is ever half written.
  - **Collision policy.** `CollisionPolicy` is `prompt` (the default), `overwrite`, `skip` or `rename`, with apply-to-all for the rest of a batch. A collision is decided by the destination's listing at delivery, never assumed. `rename` takes the first free name of the form `name (2).ext` in a stated order, the same answer for the same listing. A trusted destination is a kept folder the person marks trusted; in it, a file that AudioGubbins exported there earlier, unchanged since by its size and the hash its export record holds, is overwritten silently, and any other collision falls to the folder's policy (`REQ-ARCH-054`). Nothing overwrites by default.
  - **Exports are history, not edits.** A delivered export is recorded as an `ExportRecord` (`REQ-STOR-197`) with its settings, destination kind, file name, size, hash, the codec and its version, whether its bytes are reproducible, and its status; it is never undone, and undo says so (`REQ-STOR-198`).
  - **The interface.** The Export dialog shows the presets and, disclosed on request, every setting, with what each preset sets; Quick Edit, the region list and the File menu open it with their range. Every action is a command; the dialog, the collision prompt, the progress and the trusted-folder setting say what will happen before it happens.
- **Drivers:** `REQ-AUDIO-050`, `REQ-ARCH-054`, `REQ-AUDIO-010`, `REQ-AUDIO-143`, `REQ-ARCH-049`, `REQ-ARCH-081`, `REQ-ARCH-157`, `REQ-STOR-197`, `REQ-STOR-198`, `REQ-EDIT-014` (per-region and batch export), `REQ-EDIT-008` (Quick Edit's export), `REQ-EXEC-216` (destinations can never be assumed writable or free). The renderer already renders a range in chunks at a target rate through the canonical resampler; the layout conversion nodes exist; no dither exists. A browser file writer replaces a file only on close, and a folder listing is the only evidence of a collision.
- **Constraints:** `packages/import-export` depends on the domain, the codecs, the project format and the engine's contracts, never on a browser global; Godot's recipes depend on it, never the reverse. No export reads a whole rendered file into memory. Dither never applies to float output, and a 24- or 32-bit integer export dithers only if asked. Export recipes as persistent project objects are Phase 11's (`REQ-GODOT-119`), built on these settings.
- **Change record:** affected requirements `REQ-AUDIO-050`, `REQ-ARCH-054`, `REQ-AUDIO-010`, `REQ-AUDIO-143`, `REQ-STOR-197`, `REQ-STOR-198`, `REQ-EDIT-008`, `REQ-EDIT-014`, `REQ-GODOT-046`; affected phases 09, and 11 and 13, which build recipes and batches on these contracts. Compatibility impact: the person's preferences gain export presets and trusted folders, raising `userPreferences`; the project's state gains its last export settings, raising `projectDocument`; no migration before 1.0. Public API: `ExportSettings`, `ExportPreset`, `ExportJob`, `CollisionPolicy` in `@audiogubbins/import-export`; the staging area and delivery in `@audiogubbins/storage` and `@audiogubbins/storage-runtime`; the folder destination in `@audiogubbins/browser-storage`. Godot interchange and runtime: trusted overwrite serves rapid iteration (`REQ-ARCH-054`). PWA and browser: dialogs and folders are probed; a download is the fallback. Verification: settings and presets resolving to the same record; dither's bits from its seed; every collision policy over listed folders; a failed, cancelled and refused delivery leaving the destination unchanged; the export record's round trip; a browser test exporting a region to a folder with a collision.
- **Amends:** `ADR-0022`, whose storage worker gains the export staging area and delivery. Its other clauses stand.
- **Amended:** on 2026-10-10, by Phase 09's build, in seven clauses. The constraint: `packages/import-export` depends on the domain, the codecs and the engine's contracts (`packages/audio-graph` and `packages/audio-engine`), and not on the project format; `packages/project-format` depends on it and on the codecs, for the provenance and the export settings it keeps, so `packages/import-export` never depends on the project format. The settings: WAV takes its plain form for up to two channels in their default layout, unless its integer PCM is deeper than 16 bits, and its extensible form otherwise, as Microsoft's rule for `WAVE_FORMAT_EXTENSIBLE` has it; ADPCM, which has no extensible form, is always plain and states any other layout in `iXML`; RIFF or RF64 is decided from the whole length when the stream ends; channel conversion is `keep`, `fold`, `matrix` or `map`; noise shaping is `first-order` or the nine-tap E-weighted filter of Lipshitz, Wannamaker and Vanderkooy, which is refused at any rate but 44.1 kHz. The defaults: the rate is the project's where the codec writes it, else the lowest it writes above the project's, else its highest; AIFF and FLAC take the shallowest depth that holds the source's integer samples whole, and their deepest for float; FLAC level 5; MP3 the highest constant bit rate at the rate; Vorbis quality 10; Opus 255 kbit/s a channel, `audio`, 20 ms frames, complexity 10; AAC 128 kbit/s a channel; dither triangular, one step wide, unshaped, seed 0, for an integer depth of 16 bits or fewer, G.711 and ADPCM counting as 16, and none otherwise; the metadata policy `full`, the range the project and the file name `{project}`. The job: the render graph is `export-source`, `export-conversion` and `export-output`, the layout conversion its one node; the dither and quantisation take the rendered blocks before an integer encoder in the codec worker, not in the render worker; the dither's key is the CRC-32 of the settings written as canonical text, and its generator hashes the key, the channel and the draw's index through `lowbias32`, so no bit depends on the blocks the render came in. A file writer gives its body block by block and then a head and a tail, which complete the staged file when the stream ends. Staging: it is the cache category `staging`, given up after `temporary`, which also holds a rendition while it is decoded; at start it is cleared only when no other window holds the storage lock; and a collision prompt the person dismisses counts as skipped and keeps the staged file. Naming and collisions: the template's tokens are `{project}`, `{region}`, `{index}` (from 1, padded with zeros to the batch's width), `{date}` (`yyyy-mm-dd`, from the clock and offset the caller gives) and `{format}`; a name is NFC, each character Windows forbids and each control character becomes `_`, a Windows device name gains a leading `_`, and the name is cut to 255 bytes of UTF-8, keeping its extension; two names collide when they are equal in NFC lower case; a rename counts from ` (2)`; and a trusted overwrite needs the last record of that name to match the file's size and hash. Records and destinations: the project's last export settings are set by the undoable command `project.set-export-settings`; an export record's file holds the settings, name, size, SHA-256, codec and version, and whether its bytes are reproducible; the destination kinds gain `file` and `trusted-directory`; and trusted folders, with the records of what was exported into each, are kept beside their handles in the browser's handle database (`TrustedFolders`, the last record for each name, at most 1,024 names a folder), not in the preferences, so the person's own presets alone raise `userPreferences`. Every other clause stands.
- **Amended:** on 2026-10-10, by Phase 09's build, in the settings model and its validation. A codec's write direction states the bit rates its encoder takes, by band of sample rate and, where it is made for one, channel count: the constant bit rates it codes, and the range it holds an average to, of the stream or of each channel. LAME codes MPEG-1's table at 32, 44.1 and 48 kHz, MPEG-2's at 16, 22.05 and 24 kHz, and at 8, 11.025 and 12 kHz only MPEG-2's up to 64 kbit/s, and holds an average bit rate to the same bounds; libvorbis holds a nominal bit rate, a channel, to the union of the templates that serve the stream, and none above 50 kHz (70 kHz for six channels) or below 8 kHz, while it takes every quality from -1 to 10. An MP3 of average bit rate is LAME's ABR at that mean, and a Vorbis nominal bit rate is the average libvorbis's bit-rate manager holds the stream to. Validation refuses a bit rate outside these, naming the ranges the stream takes, before anything is rendered, and the codec worker refuses an unvalidated request by the same rule before it loads an encoder, so no encoder replaces a setting by its nearest or refuses it at encode. MP3's default is the highest constant bit rate the encoder codes at the rate. Ogg Vorbis is written in one to eight channels, the counts whose speakers Vorbis I orders, at rates up to 200 kHz. Every other clause stands.
- **Amended:** on 2026-10-12, by Phase 09's build, in the settings model, the defaults and validation. FLAC gains the setting `keepRiffChunks`, off by default: where it is on, the WAV chunks of the file's loops, cues and tuning (`smpl` and `cue `) are kept in `APPLICATION` `riff` blocks beside the Vorbis comments, which hold the first loop alone and no cue or tuning. The bit rates the browser's AAC encoder takes are probed, not stated: Chromium's Windows encoder, for one, takes only 96, 128, 160 and 192 kbit/s, for one, two and six channels at 44.1 and 48 kHz alone, and refuses the rest only when it is flushed. The probe asks `AudioEncoder.isConfigSupported` for each stream AAC-LC states, configurations 1 to 7 at each of its twelve rates, then, for each stream it accepts, every multiple of 8 kbit/s up to AAC's ceiling of 6,144 bits a channel a frame, with at most four questions open and a cancellation signal; the codec worker probes once when it starts, and the page keeps that answer for the session. Each accepted stream becomes one band of exact constant bit rates in the AAC write direction, and AAC-LC counts as encodable only where a band was found. Validation, and the codec worker by the same rule, refuses a stream with no band, naming the streams the encoder takes, and a bit rate outside its band, naming the rates it takes, before anything is rendered. AAC's default is the highest bit rate accepted for the stream after channel conversion, or, with no band, 128 kbit/s a channel up to AAC's ceiling. A preset whose bit rate the browser refuses is kept as written and reported as not exportable, with its reason, never changed. Every other clause stands.
- **Amended:** on 2026-10-13, by Phase 09's build, in the settings model, its validation, the WAV form and the defaults: WAV, AIFF and AIFF-C take integer PCM of every whole depth from 8 to 32 bits, and FLAC every whole depth from 4 to 32, the depths the readers read, FLAC's stream information states and the codec module encodes (`ADR-0091` amended); the codecs state each run once (`PCM_INTEGER_DEPTHS`, `FLAC_DEPTHS`), and the readers, the writers and validation share it. A sample is stored in the next whole byte, left-justified with its bits below the depth zero; AIFF and AIFF-C state the depth in `COMM`'s sample size. A depth is a number in `ExportSettings`, typed in the Export dialog as a bit rate is, and a depth outside its format's run or not whole is refused with the run named, by validation before anything is rendered and by the codec worker by the same rule before it opens an encoder, never rounded to one; the project and the person's presets keep it as written. WAV takes its plain form for up to two channels in their default layout unless its integer PCM is deeper than 16 bits or short of its container, as every depth of 16 bits or fewer but 8 and 16 is, and its extensible form otherwise, stating a depth short of its container in `wValidBitsPerSample`, as Microsoft's rule for `WAVE_FORMAT_EXTENSIBLE` has it. AIFF's and FLAC's default, the shallowest depth that holds the source's integer samples whole, is therefore the source's own depth, raised only where the source is shallower than the format's shallowest (8 bits for AIFF, 4 for FLAC), and their deepest, 32 bits, for float; the dither default is unchanged, triangular for an integer depth of 16 bits or fewer, and a dither the person never set follows the depth as it changes, while one they set is kept at every depth. Every other clause stands.
- **Amended:** on 2026-10-13, by Phase 09's build, in one clause. Beside a rendition being decoded and an export staged for delivery, the cache category `staging` holds a sound the session holds and no project does, such as a reference picture's (`cache/staging/session/sound-<token>`). Whoever stages or holds a file there shares the storage-wide lock for as long as it uses it, in any window: an export staged or kept for a retry or another destination, a download's staging kept until the next export, a rendition being decoded, and a held sound. So the staging is given up, by storage pressure, by the person's cleanup or at start, only with that lock held alone, and is kept whole while anyone shares it or where windows cannot be told apart; pressure relief reports it kept, and a cleanup step over it says it removed nothing. A file is removed once its user lets it go. Every other clause stands.
