# ADR-0091 — Each Format Has A Local Codec Where One Is Lawful And Mature, Built In Rust Where It Can Be, And The Browser's Codec Only Adds To It

- **Status:** Accepted
- **Decision:** Phase 09's readiness review chooses an implementation for every format and direction, so no format depends on one browser's codec where a local one is viable.
  - **The application's own codecs** (TypeScript in `packages/codecs`): reading and writing WAV, RF64, BW64, AIFF and AIFF-C in every integer depth from 8 to 32 bits, 32- and 64-bit float, G.711 A-law and µ-law, IMA ADPCM and Microsoft ADPCM; the Ogg page writer, the FLAC, MP4 (M4A) and MP3 frame-header writers, and every metadata writer of `ADR-0093`. These give the same bytes on every machine.
  - **The codec module** (Rust, compiled to one WebAssembly module, `audiogubbins-codecs.wasm`): `crates/codecs` (`audiogubbins-codecs`) decodes through Symphonia (MPL-2.0): FLAC, MP3, Vorbis, AAC-LC and ALAC, and demultiplexes Ogg, MP4/M4A, ADTS, WebM and Matroska; encodes FLAC through `flacenc` (Apache-2.0); and decodes and encodes Opus through a pure-Rust Opus implementation, which the build chooses as the first candidate that decodes the RFC 6716 and RFC 8251 test vectors within `opus_compare`'s conformance threshold, `opus-rs` (BSD-3-Clause) first. `crates/codec-bindings` (`audiogubbins-codec-bindings`) is its narrow C ABI with integer handles, its own ABI version refused on mismatch, and one import, the synchronous read of `ADR-0090`. The module is separate from the DSP module, so the engine never loads a codec it does not use.
  - **Prebuilt encoders, each a separate file.** No mature, permissively licensed MP3 or Vorbis encoder exists in Rust. MP3 is encoded by LAME 3.100 and Vorbis by libvorbis 1.3.7, as the WebAssembly builds of `wasm-media-encoders` (MIT; LAME is LGPL-2.0, libvorbis BSD-3-Clause), each loaded by the codec worker from its own file only when that format is exported. LAME stays a separate, replaceable module, its licence text and the location of its corresponding source are in the third-party notices, and nothing of it is compiled into AudioGubbins' own code (`REQ-REPO-142`).
  - **The browser's codecs add, never replace.** WebCodecs decodes HE-AAC and HE-AACv2, which no local decoder serves, where the browser probes support; elsewhere such a file is refused with the reason. AAC-LC is encoded only by the browser's encoder (WebCodecs, `mp4a.40.2`) and written into M4A by the application's own MP4 writer: the only mature, copyright-clean AAC encoder is FFmpeg's (LGPL-2.1), distributed only compiled into a single script that cannot be replaced apart from its loader, FDK-AAC's licence is not free for this project, the pure-Rust encoders are unproven, and the AAC patent position outside the United States is unsettled. Where no browser encoder is found, AAC export is unavailable with that reason, and the dialog offers Opus, Vorbis and MP3. A browser codec is never the only path for FLAC, MP3, Vorbis or Opus.
  - **The deterministic path.** Every local codec gives the same bytes for the same rendered samples and settings on every machine: WAV, AIFF, FLAC, Opus, MP3 and Vorbis exports are reproducible, and tests hold their hashes. An AAC export made by a browser encoder is not, and its export record says so (`REQ-ARCH-081`). Local codecs are the default for every format they serve.
- **Drivers:** `REQ-AUDIO-010` (local fallbacks where browsers differ), `REQ-ARCH-141` (Rust preferred for owned WebAssembly, narrow typed bindings, C libraries allowed where licensing, security, portability and determinism are met), `REQ-REPO-142` and `REQ-REPO-033` (licence review, codec patents considered apart from licences), `REQ-ARCH-049` and `REQ-ARCH-081`. No browser encodes FLAC or MP3; only Firefox encodes Vorbis; Firefox encodes no AAC; Opus encoding is missing in Firefox for Android. Symphonia decodes no Opus. The build machine compiles Rust to `wasm32-unknown-unknown` and has no C toolchain for WebAssembly, so a C library enters only as a vetted prebuilt module.
- **Constraints:** every codec runs in the codec worker. `unsafe` is allowed in `crates/codec-bindings` as in `crates/wasm-bindings`, and nowhere else. A dependency enters only with its licence in the third-party notices, its version pinned, and a test that it builds and runs in the suite. A decoder that fails a fixture fails the build; a decoder's output is never repaired after it.
- **Change record:** affected requirements `REQ-AUDIO-010`, `REQ-ARCH-049`, `REQ-ARCH-081`, `REQ-ARCH-141`, `REQ-REPO-033`, `REQ-REPO-142`; affected phase 09; Phase 03's DSP module and its ABI are unchanged. Compatibility impact: none. Public API: the codec module's ABI in `crates/codec-bindings` and its loader in `@audiogubbins/codec-runtime`. Godot interchange and runtime: the exported WAV, Ogg Vorbis and MP3 files are ordinary files Godot imports (`REQ-GODOT-133`). PWA and browser: the codec module and the two encoders are precached with the application. Verification: `cargo test --workspace`; the Opus conformance vectors, fetched on demand with their hashes (`REQ-REPO-191`); round trips of every lossless format bit for bit; lossy round trips within a stated error against the source; the hashes of local exports; a browser test of AAC export where Chromium encodes it.
- **Amends:** `ADR-0031`, whose rule that only `crates/wasm-bindings` may hold `unsafe` gains `crates/codec-bindings`. Its other clauses stand.
- **Amended:** on 2026-10-10, by Phase 09's build: `opus-rs` fails the RFC 8251 vectors, and `ropus` (BSD-3-Clause), a fixed-point port, passes all of them, so `ropus` decodes and encodes Opus; the conformance suite uses the RFC 8251 vector set, since the RFC 6716 set's decoded outputs predate it. `flacenc` encodes FLAC at 8, 12, 16, 20 and 24 bits; 32-bit FLAC frames are encoded by the codec module's own encoder, so FLAC export keeps every depth the format allows. Symphonia reads neither Matroska's `DiscardPadding` nor MP4's edit list and `iTunSMPB`, and miscounts Opus pre-skip in Ogg; the codec module reads them itself, so every decoded length is the stated one. Every other clause stands.
- **Amended:** on 2026-10-10, by Phase 09's build, in the codec module, the browser's codecs, the deterministic path and the application's own codecs. The codec module's ABI is version 1, and its one import is `ag_codec_read(source, offset, destination, length)`, the offset an `f64`; its handle table is `crates/handle-table`, shared with the DSP module, whose ABI is unchanged. The ABI also gives a stream's undecoded packets and its codec configuration, so the browser's HE-AAC decoder is fed by the module's demultiplexer; an AAC stream is taken for implicit HE-AAC when at least six of its first eight packets carry SBR. FLAC is encoded at every depth from 4 to 32 bits: by `flacenc` at 8, 12, 16, 20 and 24 bits, and by the module's own encoder, with libFLAC's LPC method, at every other depth, without stereo decorrelation at 32 bits, whose side channel would need 33; compression levels 0 to 8 make libFLAC's choices. Opus input is rounded to 16 bits, ties to even, and Opus decodes to 16 bits, as the fixed-point reference does; above two channels the encoder is given its channels in speaker-mask order and reorders them to Vorbis order itself. Matroska and WebM blocks are read by the module after Symphonia reads the tracks: `CodecDelay` trims the start of every codec and wins over Opus's pre-skip, and `DiscardPadding` trims a block's end where positive and its start where negative; `SeekPreRoll` is not read, since a decode never seeks. The Opus Ogg stream's serial number is `0x41474f70` and every MP4 creation and modification time is 0, so those files are reproducible. The application's G.711 follows ITU-T G.191; its IMA ADPCM follows the IMA reference, each `ima4` packet starting from the nine predictor bits its header holds; its Microsoft ADPCM truncates its prediction and caps its delta as FFmpeg does, choosing the best standard coefficient pair for each block; ADPCM blocks are 256 bytes a channel, doubling with the rate to 1,024 from 44.1 kHz, the last padded and `fact` holding the true length; and AIFF refuses a stream past four gibibytes. Every other clause stands.
- **Amended:** on 2026-10-10, by Phase 09's build, in the prebuilt encoders, the drivers' C toolchain, the constraints and the codec module. MP3 and Vorbis are encoded by LAME 3.100 and libvorbis 1.3.7, with the bit packer of libogg 1.3.6, built here from their release archives vendored unmodified under `third_party/`, each archive's SHA-256 recorded in its folder's README, and not taken from `wasm-media-encoders`, whose builds could express neither an average MP3 bit rate, nor a nominal Vorbis bit rate, nor Vorbis above two channels. They are built by Zig's `zig cc` at a pinned release (0.17.0), whose archive is checked against the SHA-256 its index states, for `wasm32-wasi` against Zig's wasi-libc, as reactors, with the WebAssembly features the Rust modules are held to and no fused floating-point operations, into two modules of their own files, `audiogubbins-mp3.wasm` and `audiogubbins-vorbis.wasm`; each is rebuilt only when the hash of its inputs changes. Each module has an interface of AudioGubbins' own in `native/` (Apache-2.0), at version 1, which the codec worker checks and a module of another version fails: an encoder is created from typed settings, takes planar float blocks of at most 4,096 frames in the speaker mask's order, and answers MP3 frames or Vorbis packets. LAME writes no tag or information frame, which the application's MP3 writer writes, and its reports are silenced through its own interface; libvorbis's packets are framed into Ogg by the application's Ogg writer, with the map's comments and the stream's end at the frames encoded. The worker gives each module the WASI functions it imports, and no others: a write, a seek and a close refuse, and `proc_exit` ends the encoder with its failure. Each module stays a separate, replaceable file, LAME's folder is its corresponding source, and the third-party notices quote each library's own licence files and the runtime libraries Zig links in. A C library therefore enters as vendored source built here, never as a prebuilt module. Symphonia's Vorbis decoder is its pinned release, 0.6.1, vendored under `third_party/symphonia-codec-vorbis` and patched in by the workspace: the release decodes two kinds of valid multichannel stream wrongly, a channel's residue classifications overwriting the next channel's where the partitions are not whole classwords (Vorbis I, section 8.6.2), and the coupling steps inverted first to last rather than last to first (sections 1.3.2 and 4.3.5), and a decoder's output is never repaired after it. Its README states each change and why, each is marked in the source, the notices name it as modified under MPL-2.0, and a Vorbis rendition's decoder is `Symphonia` at `0.6.1+patched`. Every other clause stands.
- **Amended:** on 2026-10-12, by Phase 09's build, in the codec module. Symphonia's AAC decoder is its pinned release, 0.6.1, vendored under `third_party/symphonia-codec-aac` and patched in by the workspace: the release refuses AAC-LC above two channels, and the patch decodes channel configurations 3 to 7, each channel of each element to the speaker ISO/IEC 14496-3 places it at, and refuses as invalid data an element other than the one the configuration places next, whose channels would reach the wrong speaker; one and two channels decode as the release decodes them. Its README states each change and why, each is marked in the source, the notices name it as modified under MPL-2.0, and an AAC-LC rendition's decoder is `Symphonia` at `0.6.1+patched`. Real AAC-LC files made by FFmpeg's own `aac` encoder hold the decoder to each channel's tone, the priming and the stated length. Every other clause stands.
