# ADR-0107 — A Looping Region's Processing Is Rendered As The Loop Sounds When It Repeats, Unless The Person Chooses Otherwise For That Loop

- **Status:** Accepted. Decided by the maintainer on 2026-10-16 (`CHG-0003`), answering Phase 10's open question Q7.
- **Decision:** A loop chooses how the processing upstream of it is rendered, by a new field of `AnchoredLoop`, `processingAcrossLoop`, one of two values:
  - **`wrapped`** (the default for every loop a command makes). The loop's body sounds as it does on every repeat after the first: a stateful processor's tail from the loop's end E carries into its start S, as a game engine plays it from the second cycle on.
  - **`from-start`**. The region's processing runs from the region's start, as `ADR-0060` renders every processed stream, so the loop's head carries the tail of the audio before it. This is the person's choice for a loop whose intro should colour its first cycle, or whose processing must match an unlooped render.

  How the region's plan realises `wrapped`, for a region of length L whose loop runs from S to E (body B = E − S):
  - **Warm-up.** The processing upstream of the loop (the asset's rack over the edited asset and the region's rack over the region, `ADR-0060`'s order) runs a second time over an input that is the loop's body repeated k times, then the region from S to L, and the plan reads that run from frame k·B. k is the smallest whole number of cycles that covers both the lead-in the chains' descriptors declare (`chainListening`'s lead-in, summed over the asset's and the region's racks, at the quality that gives the most, since a plan names no quality) and the splice's length J below, which reads that many frames of the warm-up's end, and at least one. The doubling of the body (each stream two readings of the next) holds k cycles in a number of streams that grows with log k. A processor that declares no lead-in is covered by the one cycle, as Ableton Live's "Render as Loop" and Logic Pro's "Bounce 2nd Cycle Pass" cover theirs.
  - **The intro.** Frames 0 to S are the region's ordinary run from its start, unchanged. So that the intro reaches S without a jump in the processors' state, the last J frames before S are the ordinary run faded out summed with the wrapped run's frames before S (the end of the last warm-up cycle) faded in, by equal-power fades through the domain's mix source. J is the loop's crossfade length C where C > 0, otherwise 10 ms, and never more than S. This splice lies entirely in the intro, which plays once, so no repeat hears it. A loop that starts at the region's start (S = 0) has no intro, and the region is the wrapped run from frame 0.
  - **After the loop.** Frames E to L come from the wrapped run, which continues from the loop's end, as an engine plays the region's tail when it leaves the loop after a repeat.
  - **The crossfade follows.** The loop's crossfade (`ADR-0103`) is realised after this, on the region's stream as it now stands, so the frames before S that the crossfade reads are the spliced intro's.
  - **Whole-pass processors.** A processor that measures its whole input before it plays (`ProcessorDescriptor.wholePass`, for example a loudness normaliser) measures the region's own input, never the warm-up, so its gain is one answer for both runs. The engine measures each processed stream over that stream's own input (`ChainProcessing.prepare`), and a plan cannot name another input to measure, so such a loop renders `from-start` and the Inspector names the processor and says why, rather than letting two measurements meet at S.
  - **Lengths and positions.** Nothing changes the region's length, its anchors or any position: the warm-up is read and discarded as the renderer already discards a chain's latency.
  - **Choosing.** A command that makes a loop on a region with none makes it `wrapped`; one that moves or changes an existing loop (setting its points, applying a candidate, the Create Seamless Loop workflow) keeps the loop's choice. The choice itself is set by its own command, which undoes. A loop with nothing upstream that processes, or one held `from-start` by a whole-pass processor, renders `from-start`, and the Inspector says which and why.
- **Drivers:** `REQ-GAME-121` (repeated-cycle stability; loop semantics preserved in export) and `REQ-GAME-023` (seamless-loop creation). A game repeats a loop for minutes, so the body is heard far more often than the intro's join, and a file holds one body that every repeat plays (`ADR-0093`): rendered from the region's start, the defect is heard on every cycle. The tools that render loops (Ableton Live, Logic Pro, FL Studio's "Wrap remainder") render the steady state, and those without an option teach it by hand. The maintainer asked for the choice per sound.
- **Constraints:** the plan stays the only description of the region's sound (`ADR-0051`): playback, export, the peaks, the audition plans and the loop analysis read the same plan and so hear the same loop. Rendering stays canonical and deterministic (`ADR-0032`): the warm-up is a stated input, not a cache. A loop with no processing upstream renders the same in either mode, and the mode then changes nothing a test can hear. A document that holds a loop without the field is refused, within the project document raise this field makes, with no migration before 1.0 (`REQ-STOR-052`).
- **The analysis names the cause.** When a loop renders `from-start` and its region or asset has a rack, a seam or cycle-stability check that warns or fails says that the processing runs from the region's start and that the loop can render `wrapped`. The Phase 10 plan promised the rack named in that explanation and it was not built; this ADR makes it part of the loop's sound.

Affected requirements `REQ-GAME-121`, `REQ-GAME-023`, `REQ-EDIT-014`, `REQ-AUDIO-017`, `REQ-STOR-052`; affected phase 10 (passed), whose loops gain the field and whose open question this answers, with 05 and 06, whose plan and rack rule it amends. Compatibility impact: `projectDocument` raised. Public API: `AnchoredLoop` and `LoopDefinition` gain `processingAcrossLoop`; the region command and the Inspector set it. Godot interchange and runtime: the exported file's body is the steady-state loop an engine repeats; loop points unchanged. PWA and browser: none. Verification: property tests of the region's plan in both modes against the domain's oracle; a stateful-rack fixture whose seam fails `from-start` and passes `wrapped`; the project round trip; the command, undo and Inspector tests.
- **Amends:** `ADR-0060`, whose canonical rendering clause ("a processed stream is rendered from its own start") now holds for a looping region only where its loop renders `from-start`; `ADR-0103`, whose crossfade is realised after the wrapped render. Their other clauses stand.
