# ADR-0101 — An Asset Group Is A Node Of One Tree, Its Policy Is Resolved Field By Field With The Owner Named, And Its Processing Is Heard Through The Member's Shared Rack

- **Status:** Proposed
- **Decision:** `REQ-GAME-120`'s hierarchical groups are values of `packages/game-audio`, kept in the project and changed only by project commands with inverses.
  - **The tree.** A `GameAssetGroup` has an identifier, a name, an optional parent and the policy it sets. The groups form one forest: a parent exists, no group is its own ancestor, and siblings' names differ in NFC lower case. A name is one path segment, 1 to 128 characters, with no `/`, control character or surrounding space, so `Footsteps/Grass` is the path of the group `Grass` under `Footsteps`, never a name.
  - **Members.** A member is a region or an asset (`GroupMember`), each in at most one group, so its effective policy has one answer. A group's members are held in the order they were assigned, which is the order the preview chooses among and `{number}` counts by (`ADR-0102`); reordering and weights are Phase 13's (`REQ-GAME-112`). A variation set and an event join the member union when Phases 13 and 11 make them; no arm is made before them. A region or asset in a group cannot be removed by the project's remove command until it leaves the group, as a chain something names cannot (`ADR-0060`); the interface's delete and split commands leave and rejoin in the same step.
  - **The policy.** `InheritedPolicy` is a record of optional fields, one per default `REQ-GAME-120` names: `processing` (an `EffectChainId`, or `none`), `loudness` (an integrated target in LUFS, a tolerance in LU and an optional true-peak ceiling in dBTP), `exportProfile` (`ADR-0102`), `naming` (a naming template), `destination` (a relative folder path), `playback` (the runtime variation and voice rules the preview runs, `ADR-0104`), `bus` (the runtime bus a member plays on, by name) and `tags`. A field a group does not set is inherited; a field it sets is set there, never copied into its descendants.
  - **Overrides.** A member's overrides are a record of the same fields but `processing` and `tags`. An override is a value set on the member; resetting it to inherited removes it. No field holds a hidden default: an unset field with no ancestor that sets it is `unset`, and what consumes it says what it does without one.
  - **Resolution.** `resolvePolicy(state, member)` answers, for every field, the value, its source (the member's override, the nearest group that sets it, or `unset`) with that group's identifier and path, and the values of the ancestors it shadows. It walks the member's group to the root once, field by field, so the answer depends only on the state and is the same in any order of evaluation; `resolveAll` answers every member in one pass. Tags are the one additive field: the union, in sorted order, of every ancestor's tags and a region's own `Region.tags`, each tag with the groups and member that give it. An invalid value (a template that does not read, a path segment refused, a profile a member's audio cannot take) is a failure that names the field and its owner, group or member, as the packet's failure rule requires.
  - **Processing is heard through the rack.** The plan is the only description of an edited sound (`ADR-0051`), and the domain's plan knows no group, so an inherited processing chain is realised as the member's rack naming the group's chain: a shared chain (`ADR-0060`). A member's processing is *inherited* when its rack names the chain its nearest setting group names, and *its own* otherwise, its own rack or none; no flag records it, so it cannot disagree with what is heard. Resetting it to inherited sets its rack to that chain. A game command that changes what a member inherits, assigning it, moving it or its group, or setting a group's `processing`, re-points in the same command the rack of every member that inherited the old chain, so one undo restores both; a chain a group names enters and leaves the project with it, and is not removed while a group or a member names it.
  - **Loudness is a target, not a hidden processor.** The `loudness` field states what a member should measure at. A conformance report measures members in the detection worker against their effective target and tolerance, and the Normalise Game SFX workflow realises the target as a loudness-normalisation slot at the end of the group's chain or a member's own rack (`ADR-0105`). Nothing is normalised because a field says so.
  - **Bus and playback rules are authored rules.** `bus` names a runtime bus as a game engine knows it, not one of the editor's buses, which no phase has built; the preview routes by it (`ADR-0104`) and Phase 11 maps it. `playback` holds the rules the preview runs and that Phase 11's runtime resources are generated from.
- **Drivers:** `REQ-GAME-120` (explicit, inspectable inheritance; overrides distinguishable and resettable; no hidden state), the packet's invariants ("inheritance is explicit and overridable; no hidden magic settings") and failure rule ("invalid inherited settings must identify the owning group/override"), `ADR-0051` and `ADR-0060` (the plan is the only description of a sound; sharing is naming one chain), `REQ-EDIT-073`. A group processing stage added to the plan would make the domain know games, against the packet's dependency rule, and a flag beside the rack would be a second record that could disagree with what is heard.
- **Constraints:** resolution is pure and total over a valid state, and the project format refuses a document whose groups break the tree, membership or chain rules. Every group change is a project command with an inverse (`ADR-0106`). A member's tags stay `Region.tags`, the region's own; assets have no tags of their own in this phase.
- **Change record:** affected requirements `REQ-GAME-120`, `REQ-GAME-023` (naming templates, loudness matching, game-oriented presets), `REQ-EDIT-014` (shared processing chains); affected phases 10, 11 (which generates runtime resources from groups, rules and buses) and 13 (whose variation sets join the member union and inherit the same policy). Compatibility impact: the project document gains the game-audio state (`ADR-0106`). Public API: `GameAssetGroup`, `GroupMember`, `InheritedPolicy`, `PolicyOverrides`, `EffectivePolicy`, `resolvePolicy`, `resolveAll`. Godot interchange and runtime: buses and playback rules are what Phase 11 maps. PWA and browser: none. Verification: resolution tested directly over generated forests, deterministic and order-independent; every invalid field's failure naming its owner; the rack realignment of every game command and its inverse; the project round trip.
- **Related requirements:** `REQ-GAME-120`, `REQ-GAME-023`, `REQ-GAME-112`, `REQ-EDIT-014`, `REQ-EDIT-073`, `REQ-ARCH-153`.
