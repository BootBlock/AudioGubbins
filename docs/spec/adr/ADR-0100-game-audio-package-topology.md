# ADR-0100 — Game-Audio Tooling Is Three Packages Over The Editing, DSP And Export Contracts, And Godot Knows Nothing Of Them Yet

- **Status:** Proposed
- **Decision:** Phase 10's code is three new packages, each with one responsibility and one direction between them, and additions to existing packages at the seams those packages already own. No package named `export-recipes` is made: export recipes as project objects are Phase 11's (`REQ-GODOT-119`), and the game layer of export is a module of `packages/game-audio` (`ADR-0102`).
  - `packages/game-audio` (`@audiogubbins/game-audio`, portable) is the game-audio domain as values: asset groups, membership, inherited policy and its resolution with provenance (`ADR-0101`), naming templates, game export profiles, destination paths and the game export plan (`ADR-0102`), and the game preview's rules, scenarios, seeded selection, voice model, attenuation and the preview plan (`ADR-0104`). It depends on `packages/domain` and `packages/import-export` alone, reads no clock, browser global or thread, and is given the processor catalogue it builds a preview chain from as an argument.
  - `packages/loop-analysis` (`@audiogubbins/loop-analysis`, portable) is seamless-loop analysis: the metrics, the candidate search, the micro-crossfade suggestion and the loop audition plans (`ADR-0103`). It depends on `packages/domain` and `packages/audio-engine` (the canonical primitives, the STFT and `PcmSource`), and reads audio only through a `PcmSource` it is given, in bounded windows.
  - `packages/guided-workflows` (`@audiogubbins/guided-workflows`, portable) is the guided workflows as deterministic planners: each turns a subject, its options, the project state and analysis results into a list of ordinary project-command invocations dispatched as one history step (`ADR-0105`). It depends on `packages/domain`, `packages/game-audio`, `packages/loop-analysis`, `packages/processors`, `packages/import-export` and `packages/project-commands`, and dispatches nothing itself.
  - **Seams in existing packages.** `packages/project-format` keeps the game-audio state in `ProjectState.gameAudio` (`ADR-0106`) and depends on `packages/game-audio`; `packages/project-commands` gains the game commands in `src/game/` and depends on `packages/game-audio`; `packages/history` diffs the game-audio state; `packages/detection-runtime` runs a loop analysis and a loudness measurement as requests of the detection worker it already is, depending on `packages/loop-analysis` (amending `ADR-0061`); `packages/domain` gains the loop crossfade in a region's plan and the varispeed stream (`ADR-0103`, `ADR-0104`), and the counter-based draw moved from `packages/import-export` so the dither and the preview share one generator; `packages/audio-engine` gains the zero-crossing boundary moved from `packages/waveform`, which keeps its search over it; `packages/processors` gains the `pan` processor type; `packages/audio-runtime` and `apps/web/src/audio` gain the continued programme (`ADR-0104`); `packages/storage`, `packages/storage-runtime` and `packages/browser-storage` deliver into a relative folder of a chosen or trusted folder (`ADR-0102`); `apps/web` gains the game-audio panels and commands; `packages/workspace` places them in the Game Audio preset.
  - **Direction.** `domain` ← `import-export` ← `game-audio` ← `project-format` ← `project-commands` ← `guided-workflows` ← `apps/web`; `domain`, `audio-engine` ← `loop-analysis` ← `detection-runtime`, `guided-workflows`, `apps/web`. Nothing below `apps/web` imports a Godot package, and the dependency cruise holds `packages/game-audio`, `packages/loop-analysis` and `packages/guided-workflows` to that, so Phase 11's packages depend on these and never the reverse (`REQ-GODOT-107`, the packet's dependency rule).
- **Drivers:** the packet's owned modules and its dependency rules ("game-audio domain depends on generic editing/DSP/export contracts"; "must not import Godot-specific runtime/editor types"); `REQ-EXEC-136.3` cohesive boundaries; the working agreement's G1 (one responsibility per module, a domain package takes its I/O through an injected port) and G2. The project format already depends on the export package for `ProjectState.exportSettings` (`ADR-0092` amended), so game state kept beside it follows the same direction. The workflows compose project-command invocations, so they cannot live below `packages/project-commands`, and `packages/project-commands` cannot depend on them without a cycle through the project format.
- **Constraints:** the three packages know no React, browser global or storage; analysis runs in the detection worker, never on the page; the game commands are project commands with inverses, and the interface invokes commands only (`REQ-EDIT-073`). A package added here is registered in `tools/sync-workspace-graph.mjs`, the layering of `tests/architecture/dependency-rules.test.ts`, an owns-nothing-else rule of `.dependency-cruiser.cjs` and the public-contract record.
- **Change record:** affected requirements `REQ-GAME-023`, `REQ-GAME-075`, `REQ-GAME-120`, `REQ-GAME-121`, `REQ-GAME-122`, `REQ-EXEC-136`, `REQ-EXEC-184`; affected phases 10, and 11 and 13, which build on these packages (Phase 13's packet also lists `packages/game-audio`, which it extends). The packet's owned module "packages/export-recipes game layer" is realised as `packages/game-audio/src/export/` and its owned modules gain `packages/guided-workflows`, recorded in `docs/todo/phase-10-game-audio-tooling.md` as a packet amendment owed. Compatibility impact: none by itself (`ADR-0106` raises the document). Public API: the three packages' entry points. Godot interchange and runtime: none; Phase 11 consumes these contracts. PWA and browser: none. Verification: the layering and the dependency cruise, `pnpm test:architecture`, the scope projects.
- **Amends:** `ADR-0061`, whose detection worker also runs a loop analysis and a loudness measurement of a target's processed audio; `ADR-0040` amended, whose `packages/waveform` keeps its zero-crossing search over the boundary `packages/audio-engine` now states. Their other clauses stand.
- **Related requirements:** `REQ-GAME-023`, `REQ-GAME-075`, `REQ-GAME-120`, `REQ-GAME-121`, `REQ-GAME-122`, `REQ-GODOT-107`, `REQ-GODOT-119`, `REQ-EDIT-073`, `REQ-EXEC-136`, `REQ-EXEC-184`.
